# 데모 데이터

```bash
python3 scripts/make_demo_data.py     # sample_data/generated/ 에 3개 생성
```

## 왜 내려받지 않고 생성하는가

공개 저장소에 남의 데이터셋을 넣으면 그쪽 라이선스를 같이 지게 된다. 잘 알려진 표 형식 데이터셋들의 조건이 제각각이라 "데모였을 뿐"은 변명이 되지 않는다. 여기 있는 건 누구의 데이터도 아니다.

시드가 고정돼 있어서, 방문자가 생성한 파일은 이 문서가 설명하는 그 파일이다.

| 파일 | 행 | 타깃 | 용도 |
|---|---|---|---|
| `customer_churn.csv` | 1200 | `churn` (이탈률 23%) | 분류. 정상 데이터 |
| `customer_churn_leaky.csv` | 1200 | `churn` | 위와 동일 + 누출 3개 |
| `bike_signups.csv` | 1200 | `signup_count` | 회귀 |

`customer_churn.csv`의 이탈률은 23%다. 균형을 맞추지 않은 건 의도다 — 전부 "no"라고 답하는 모델이 정확도 77%를 받기 때문이고, **정확도만으로는 쓸모없는 모델을 걸러낼 수 없다**는 걸 데모에서 직접 보여줄 수 있어야 한다.

## 심어둔 누출 세 가지

`customer_churn_leaky.csv`에는 서로 다른 방식으로 새는 컬럼이 셋 있다. 아무 문제 없는 데모로는 이 제품의 핵심 기능이 작동하는 걸 보여줄 수 없다.

| 컬럼 | 새는 방식 | 어떻게 잡히는가 |
|---|---|---|
| `churn_reason` | 이탈자에게만 값이 있다 | 결측 패턴이 타깃과 일치 |
| `account_closed_date` | 결과 확정 이후 채워진다 | 결측 패턴이 타깃과 일치 |
| `exit_survey_score` | 클래스를 거의 완전히 분리한다 (8.43 vs 2.08) | 단일 컬럼 분리도 |

셋 다 `exclude` 판정을 받고, 깨끗한 쪽에서는 제외 권고가 나오지 않는다.

```
누출 심은 데이터   위험도=high     제외=[churn_reason, account_closed_date, exit_survey_score]
깨끗한 데이터      위험도=medium   제외=[]
```

## 이 데이터가 잡아낸 것

데모를 만드는 과정 자체가 검사기의 결함을 드러냈다. 원래 검사는 **컬럼 이름만** 봤고, 그래서 이런 상태였다.

- `exit_survey_score`는 잡혔지만 **분리력 때문이 아니라 이름에 `score`가 들어 있어서**였다. `wellbeing_index`로 이름만 바꾸자 — 값도 분리력(8.43 vs 2.08)도 그대로인데 — 완전히 통과했다.
- `account_closed_date`는 결과 이후 정보인데 `keep` 판정이었다.
- 명백한 누출 셋이 있는 데이터에서 **제외 권고가 0건**이었다. 어떤 것도 `high`에 닿지 못했기 때문이다.

이름은 컬럼에 대한 힌트고, 힌트는 이름을 바꾸는 순간 사라진다. 그래서 컬럼이 **무엇을 하는지** 측정하는 검사를 추가했다(`_separation_power`).

측정하면서 두 가지가 더 나왔다.

**결측 자체가 누출이다.** `churn_reason`은 이탈자에게만 값이 있어 분리도가 1.0이어야 하는데 0이 나왔다. pandas가 빈 문자열을 NaN으로 읽고 `dropna()`가 비이탈자를 전부 버려서, 남은 건 단일 클래스뿐이라 "측정 불가"가 됐다. 증거를 버리고 증거가 없다고 결론 내린 셈이다. 실무에서 가장 흔한 누출 형태가 정확히 이거다 — 사건이 일어난 행에만 채워지는 필드.

**고유값이 많다고 건너뛰면 안 된다.** 처음엔 고유값 비율 95% 이상인 컬럼을 식별자로 보고 측정에서 제외했다. 그런데 연속형 실수 컬럼은 거의 항상 전부 다른 값이다. 즉 **숫자 누출이 숨을 만한 컬럼 대부분이 측정에서 빠졌다.** `exit_survey_score`가 걸린 건 소수점 2자리 반올림 덕에 중복이 생겼기 때문이고, 반올림하지 않은 같은 데이터는 그대로 통과했다. 지금은 이 규칙을 문자열 컬럼에만 적용한다.

## 남은 한계

- 분리도 측정은 **이진 분류 타깃에만** 동작한다. 회귀와 다중 클래스는 다른 척도가 필요하고, 지금은 `None`을 반환해 이름 기반 신호로 되돌아간다.
- **단일 컬럼만** 본다. 두 컬럼을 합쳐야 타깃이 재현되는 조합 누출은 못 잡는다.
- 분리도가 높다고 반드시 누출은 아니다. 진짜로 강력한 예측 변수일 수도 있다. 그래서 결과는 `exclude` *권고*이고, 판단은 사람이 한다.
